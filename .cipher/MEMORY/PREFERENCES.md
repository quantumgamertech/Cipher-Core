# Preferences

Stores stable collaboration, engineering, and presentation preferences.

## Categories

- communication;
- engineering workflow;
- design and UX;
- testing and validation;
- reporting;
- release and deployment.

## Rules

- Record explicit preferences separately from inferred patterns.
- Current task instructions override general preferences.
- Preferences cannot weaken [SAFETY.md](../SAFETY.md).
- Remove or supersede preferences that no longer apply.

## Canonical collaboration preferences

- Be clear, direct, and evidence-driven.
- Prefer targeted production-ready solutions over speculative fixes.
- Preserve existing behavior unless change is authorized.
- Identify exact failure boundaries and use logs as evidence.
- Make instructions actionable.
