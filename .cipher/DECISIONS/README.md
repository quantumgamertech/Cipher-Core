# Architectural Decisions

This directory contains permanent Architecture Decision Records (ADRs).

## When an ADR is required

Create an ADR when a change:

- establishes or alters a subsystem boundary;
- introduces a durable integration pattern;
- selects between meaningful architectural alternatives;
- changes security, safety, memory, identity, or provider policy;
- creates compatibility or migration obligations;
- would be expensive or confusing to reverse later.

## Required sections

- Date
- Status
- Context
- Decision
- Alternatives or rejected approaches
- Consequences
- Validation
- Rollback or supersession

## Status values

- Proposed
- Accepted
- Superseded
- Retired

Do not rewrite an accepted record to make history look current. Add a new ADR and mark the older record superseded.
